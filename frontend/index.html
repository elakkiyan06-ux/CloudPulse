STEP 1 — VERIFY MANAGED DATABASE STATUS

Executes an active ping test against the configured AWS RDS PostgreSQL / local instance, measuring network latency, pool status, and PostgreSQL engine version.

STEP 2 — INGEST REAL-TIME WEATHER TELEMETRY

Requests current weather observations from Open-Meteo API across 8 predefined cities, validates payloads, and inserts into AWS RDS PostgreSQL with duplicate prevention.

STEP 3 — RUN READ BENCHMARK

Executes high-resolution SELECT queries on the real weather_observations table in AWS RDS, measuring min, average, median, p95, and throughput.

STEP 4 — RUN WRITE BENCHMARK WITH LATENCY DECOMPOSITION

Obtains fresh live data from Open-Meteo, inserts into AWS RDS, and isolates external API network latency vs actual database write time.

STEP 5 — CAPTURE BASELINE QUERY PLAN

Runs EXPLAIN ANALYZE on a temporal location query, capturing planner node type (Seq Scan) and execution time.

STEP 6 — APPLY COMPOSITE B-TREE INDEX

Safely creates the composite index idx_weather_loc_time on weather_observations (location_name, observation_time DESC).

STEP 7 — PROVE BEFORE VS AFTER & HONEST ANALYSIS

Reruns the exact same query with the index active, compares baseline vs optimized latency, and renders honest engineering findings.

STEP 8 — GENERATE PERFORMANCE AUDIT REPORT

Generates and downloads the final performance report summarizing real Open-Meteo observations, AWS RDS PostgreSQL performance, and optimization findings.
